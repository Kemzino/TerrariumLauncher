# Формат маніфесту збірки

Приклад: [`manifest.example.json`](./manifest.example.json).

Маніфест — єдине джерело правди про те, з чого складається версія збірки.
Лаунчер ніколи не «сканує» папку і не здогадується: він порівнює **попередній маніфест**,
**стан на диску** і **новий маніфест**.

## Поля верхнього рівня

| Поле | Призначення |
|---|---|
| `formatVersion` | версія самого формату; лаунчер відмовляється читати незнайому |
| `pack`, `version` | ідентифікатор збірки і її версія (semver або дата) |
| `minecraft`, `loader` | що саме встановлювати; передається в `daedalus`-метадані як є |
| `launcher.minVersion` | якщо лаунчер старіший — просимо оновитись, а не ламаємо збірку |
| `files[]` | повний список керованих файлів (див. нижче) |
| `overrides` | zip з нашими власними файлами; посилання `overrides:<шлях>` у `files[]` беруться звідси |
| `signature` | ed25519-підпис над канонічним JSON без самого поля `signature` |

## Політики файлів

Політика — це відповідь на питання «що робити, якщо гравець змінив цей файл».

| `policy` | Поведінка | Для чого |
|---|---|---|
| `managed` | завжди приводимо до цільового хешу; змінену версію — в бекап | моди, бібліотеки |
| `seed` | кладемо **лише якщо файлу немає**; далі не чіпаємо ніколи | конфіги, `options.txt`, кейбінди |
| `merge` | якщо гравець не правив — перезаписуємо; якщо правив — 3-way merge | конфіги, де ми міняємо окремі ключі |
| `force` | перезаписуємо завжди, незалежно від змін | те, без чого збірка не працює |

`mergeFormat` (`toml` \| `json` \| `ini` \| `properties`) потрібен лише для `merge`.
Базою для 3-way merge служить pristine-копія файлу з **попередньої** версії, яку лаунчер
тримає в `.terrarium/pristine/`.

## Опційні моди

```json
"optional": { "id": "shaders", "default": false }
```

Файли з однаковим `optional.id` вмикаються/вимикаються разом. Вибір гравця зберігається
в стані лаунчера і **переживає оновлення**: якщо гравець вимкнув `shaders` у 1.4.1,
у 1.4.2 вони не увімкнуться самі.

## Джерела завантаження

`downloads[]` — список дзеркал, пробуються по черзі:

- звичайний URL (Modrinth/CurseForge CDN) — основний шлях для модів;
- `overrides:<шлях>` — файл лежить у нашому `overrides.zip`.

Моди **не кладемо** у власні релізи: вони качаються з CDN автора за хешем. У GitHub Releases
їде лише `manifest.json` і `overrides.zip`.

## Що робить підпис

Підписується канонічний JSON без поля `signature`. Публічний ключ вшитий у лаунчер;
`keyId` дозволяє ротацію. Без цієї перевірки компрометація pack-репозиторію означає
виконання довільного коду на машинах усіх гравців.
